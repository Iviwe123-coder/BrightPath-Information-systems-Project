Adapting and Customising Information Systems

Topic 5 · adapting systems to institutional needs

BrightPath’s systems need to support its academic and administrative work while remaining supportable over time. Before changing software, managers should understand the problem in the process, then choose the smallest reliable change that addresses it.

Configuration and customisation

Configuration uses built-in settings; extensions add supported features; customisation changes standard behaviour. Direct changes to vendor code can make upgrades and support harder. Terms vary by product, so check its documentation. (Oracle example)

Build or buy

To connect the SMS to the LMS, BrightPath could configure a supported connector, buy middleware or build an interface. Compare accuracy, speed, alerts, access controls, portability, cost, skills, support and maintenance. Start with the supported connector if it meets the need and reports failures clearly.

Change management and training

Involve academic staff, administrators, IT and student representatives. Map the process, pilot the change, train users by role and provide launch support. Use feedback and error reports to improve the rollout.

Long-term maintenance

Budget for access reviews, integration upkeep, testing and upgrades. Document each change, its owner and rollback plan. Test updates before production where the vendor supports that process. (Oracle example)
